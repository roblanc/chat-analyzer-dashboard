# CLAUDE.md — Chat Analyzer Dashboard

> AI assistant guide for the `chat-analyzer-dashboard` repository.

## Project Overview

An AI-powered WhatsApp group chat analytics dashboard. It combines:
- **React 19 frontend**: Bento-grid layout with charts, stats, and an AI Q&A widget
- **Netlify serverless function**: Intelligent Q&A backed by Google Gemini (with OpenRouter fallback)
- **Build-time data pipeline**: WhatsApp transcript → indexed chunks + pre-computed dashboard stats

The five group members are: **Unde**, **Marius Motoi**, **Baldo**, **Vasile**, **R** (Robert).

## Development Workflow

### Prerequisites

- **Node 20** (use `nvm use` — version locked in `.nvmrc`)
- A `netlify/data/chat.txt` WhatsApp export (not in git)
- A `GEMINI_API_KEY` environment variable

### Initial Setup

```bash
nvm use
npm install
```

Copy your WhatsApp archive to `netlify/data/chat.txt`.

Create a `.env.local` file:
```
GEMINI_API_KEY=your_key_here
OPENROUTER_API_KEY=optional_fallback_key
```

### Local Development

```bash
npm start           # Runs prestart (builds index + stats) then starts React dev server
npx netlify dev     # Starts React dev server AND local Netlify functions (port 8888)
```

`npm start` automatically runs `build:chat-index` and `build:dashboard-stats` before launching.
Use `npx netlify dev` when you need to test the `/ask` AI endpoint locally.

### Build Scripts

```bash
npm run build:chat-index      # Parses chat.txt → netlify/data/chat.index.json
npm run build:dashboard-stats # Computes stats → public/dashboard-stats.json
npm run build                 # All of the above + react-scripts build → build/
```

### Tests

```bash
npm test            # Jest in watch mode
```

Tests use React Testing Library. The test suite is minimal (CRA default + light coverage). When adding components, add RTL tests in `src/`.

## Key Conventions

### React Components

- **Functional components with hooks only** — no class components
- `useEffect` for data fetching and subscriptions (always return cleanup)
- `useMemo` for derived data or expensive computations
- Markdown rendering: always use `marked` + `DOMPurify.sanitize()` before setting `dangerouslySetInnerHTML`

```js
// Correct pattern for markdown rendering
import { marked } from 'marked';
import DOMPurify from 'dompurify';
const html = DOMPurify.sanitize(marked.parse(markdown));
```

### Styling

- **Dark mode by default** using CSS variables (no light mode currently)
- **Bento grid** layout: 12-column CSS grid, cards use `backdrop-filter: blur`
- Colors are semantic CSS variables: `--color-indigo`, `--color-violet`, `--color-pink`
- Chart colors: `MessageCount` = indigo, `DailyActivity` = violet, `HourlyActivity` = pink
- Avoid inline styles; use CSS classes or variables

### JavaScript

- **Scripts** (`scripts/`) use CommonJS (`require`/`module.exports`) and run in Node
- **Frontend** (`src/`) uses ES6 modules (`import`/`export`)
- **Netlify function** (`netlify/functions/ask.js`) uses CommonJS
- Text normalization: always lowercase + NFD diacritic removal for Romanian text matching

```js
// Standard normalization pattern used throughout
const normalize = (s) => s.toLowerCase().normalize('NFD').replace(/[\u0300-\u036f]/g, '');
```

### Data Flow

```
chat.txt → build-chat-index.js → chat.index.json  (used by ask.js at runtime)
chat.txt → build-dashboard-stats.js → dashboard-stats.json  (served as static JSON)
public/knowledge.md  (static, hand-maintained knowledge base)
        ↓
     App.js fetches both dashboard-stats.json + knowledge.md
        ↓
   Charts + AskAI component receive data as props
```

## Serverless AI Function (`netlify/functions/ask.js`)

### Endpoint

```
POST /.netlify/functions/ask
Body: { "question": "string" }
Response: { "answer": "string", "sources": [...], "model": "string" }
Error:    { "error": "string", "details": "string" }
```

### Architecture

1. **Intent detection** — classifies question as `analysis`, `profile`, or `smartness`
2. **Author extraction** — finds group member names in the question
3. **Context retrieval** — TF-IDF scoring against precomputed `chat.index.json`:
   - Tokenizes question, removes Romanian + English stopwords
   - Expands tokens with intent-specific hints
   - Scores chunks by IDF-weighted term overlap
   - Selects top-K chunks up to char limit
4. **Prompt construction** — injects knowledge.md, stats, author profiles, chat examples
5. **AI generation** — tries Gemini models in order, falls back to OpenRouter free models
6. **Response** — returns markdown answer + source metadata

### Key Constants

| Constant | Value | Purpose |
|---|---|---|
| `MAX_CONTEXT_CHARS` | 10,000 | Context window for analysis/general questions |
| `MAX_CONTEXT_CHARS_PROFILE` | 18,000 | Context window for profile questions |
| `CHAT_CHUNK_TARGET_CHARS` | 1,600 | Target size per chat chunk |
| `REQUEST_TIMEOUT_MS` | 25,000 | AI API timeout (Netlify 26s limit) |

### AI Providers & Retry Logic

- **Primary**: Google Gemini (`GEMINI_API_KEY`)
  - Default models: configurable via `GEMINI_MODELS` env var
  - Retries on HTTP 429, 500, 503, 504
- **Fallback**: OpenRouter (`OPENROUTER_API_KEY`)
  - Prioritizes free models (`:free` suffix)
  - Exponential backoff on rate limits

### Source Types in Response

| `kind` | Description |
|---|---|
| `chat` | Chat message chunk with `start`/`end` timestamps and `authors` |
| `stats` | Dashboard statistics snippet |
| `authorProfile` | Computed author profile (message habits, top words) |
| `examples` | Temporal message examples (early/mid/recent) |

## Chat Indexing (`scripts/build-chat-index.js`)

### Input Format

WhatsApp export format (Romanian locale):
```
[DD.MM.YYYY, HH:MM:SS] Author Name: Message text
```

### Parsing Rules

- Strips unicode directional marks (`\u200e`, `\u202a`, `\u202c`)
- Multi-line messages are concatenated to the previous entry
- Media omissions (`<Media omis>`, image/audio/video/sticker) are cleaned or skipped
- System messages (group notifications) are filtered out

### Author Aliases

Canonical names to watch for in parsing:
- `Unde`, `Marius Motoi`, `Baldo`, `Vasile`, `R`

If a new member appears in the chat, update `CANONICAL_AUTHORS` in `build-chat-index.js` and `build-dashboard-stats.js`.

## Dashboard Stats (`scripts/build-dashboard-stats.js`)

### Data Periods

- **Legacy period**: June 11 → October 29, 2025 (141 days, pre-computed from external source)
- **Incremental period**: October 30, 2025 → current date (parsed from `chat.txt`)
- **Combined**: sum of both

### Output Shape (`public/dashboard-stats.json`)

```json
{
  "version": 1,
  "generatedAt": "ISO timestamp",
  "labels": { "authors": [], "weekdays": ["Luni",...], "hours": ["00",...] },
  "legacy": { "period": {}, "authors": {}, "weekdayCounts": [], "peakHour": {}, "peakWeekday": {} },
  "incremental": { "period": {}, "authors": {}, "totalMessages": 0, "hourCounts": [], "weekdayCounts": [], ... },
  "combined": { "authors": {}, "totalMessages": 0, "weekdayCounts": [], "peakWeekday": {} }
}
```

Weekday order is **Monday-first** (index 0 = Monday / Luni).

## Common Tasks

### Add a new chart

1. Create `src/components/MyChart.js` using `react-chartjs-2`
2. Register needed Chart.js elements at the top of the file
3. Accept `stats` as a prop; provide fallback default data
4. Import and render in `src/App.js`
5. Add CSS grid placement in `src/App.css`

### Change AI model priority

Edit the `GEMINI_MODELS` environment variable (Netlify UI or `.env.local`), or modify the default model array in `netlify/functions/ask.js`.

### Update the knowledge base

Edit `public/knowledge.md` — it is served statically and read by both the frontend and the AI function at runtime.

### Add a new group member

1. Add their name to `CANONICAL_AUTHORS` in both `scripts/build-chat-index.js` and `scripts/build-dashboard-stats.js`
2. Add their avatar PNG to `public/avatars/`
3. Update `src/components/AskAI.js` suggestion grid
4. Rebuild: `npm run build:chat-index && npm run build:dashboard-stats`

## Architecture Decisions

| Decision | Rationale |
|---|---|
| Build-time indexing | Netlify functions have cold-start constraints; pre-computing the TF-IDF index keeps latency low |
| TF-IDF retrieval | Simple, no vector DB needed; works well for short-form WhatsApp messages |
| Romanian stopword filtering | Prevents common Romanian words from polluting term weights |
| Dual AI provider | Gemini is primary; OpenRouter free tier is fallback to avoid hard failures |
| Marked + DOMPurify | Enables rich AI markdown responses safely in the browser |
| Legacy + incremental stats split | Preserves pre-computed stats from before the current chat archive window |
